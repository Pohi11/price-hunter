# Security model

Price Hunter fetches **arbitrary user-supplied URLs** from inside a cloud account and stores users' email addresses. Those two facts shape most of the decisions below.

## Threats and controls

| Threat | Controls | Where |
|---|---|---|
| **SSRF**: a user URL reaches cloud metadata, the Lambda runtime API, or internal hosts | 4 layers: input validation (scheme, ports, no IP literals or userinfo, public-suffix domains), **dial-time IP check on every connection including redirects** (defeats DNS rebinding), redirect re-validation, containment (`Proxy: nil`, size caps, least-privilege role, no VPC) | ADR-007, `internal/urlx`, `internal/fetch/ssrf.go` |
| Response-based attacks (huge pages, gzip bombs, slowloris) | 3 MB cap **after** decompression, connect/TLS/header/total timeouts, content-type allowlist | `internal/fetch/client.go` |
| Broken authentication | Cognito managed login (code + PKCE); API Gateway validates JWT signature, issuer, audience and expiry before Lambda runs; self-signup off by default | `infra/modules/app/{auth,api}.tf` |
| Broken authorization (IDOR) | Every key is derived from the token's `sub`, never from the request. Product-scoped reads check ownership first. Other users' products return 404. Cursors carry only sort keys. | `internal/products`, `internal/store`; tested by `TestOwnershipIsolation` |
| Injection / malformed input | Strict JSON decoding (unknown fields, trailing data, 16 KB cap); validated money, URL, frequency and name; no query language built from input; HTML emails escaped by `html/template` | `internal/api`, `internal/notify/render.go` (tested) |
| Abuse and cost attacks | API Gateway stage throttling; per-user product quota (transactional); 5-minute manual-check cooldown; 1-hour minimum check interval; Lambda concurrency caps; AWS Budgets alerts | `products`, `store`, Terraform |
| Email address exposure | Stored only in the profile item (encrypted at rest); **hashed in logs** (`telemetry.Email`); never in metrics or URLs; only *verified* Cognito emails are trusted | `internal/telemetry/log.go`, `internal/auth/apigw.go` |
| Secrets | No long-lived AWS keys: CI uses **GitHub OIDC** with roles restricted to protected environments. No secrets in the repo (gitleaks in CI). The demo-store admin token is generated by Terraform. | `infra/bootstrap`, `.github/workflows` |
| Over-privileged compute | One IAM role per function with specific actions on specific ARNs: the scheduler can only `Query` the GSI; the worker can write snapshots only under `snapshots/*`; SES sending is restricted to the configured `From` address | `infra/modules/app/lambdas.tf`, `email.tf` |
| Transport security | HTTPS only (CloudFront redirect, API Gateway), TLS 1.2+, HSTS preload, SES `tls_policy = REQUIRE` | `frontend.tf`, `email.tf` |
| Browser-side attacks | Strict CSP, `frame-ancestors 'none'`, nosniff, a strict referrer policy; tokens in sessionStorage; the ID token is sent only to the API origin | `frontend.tf`, `web/src/auth.tsx` |
| Supply chain | Dependabot (Go, npm, Actions, Terraform), govulncheck, trivy dependency and IaC scans, lockfiles committed, `npm ci` in CI | `.github/` |

## Accepted risks (scan exceptions)

`.trivyignore.yaml` lists each accepted IaC finding with its reasoning. In short:

- **Customer-managed KMS keys** (S3, DynamoDB, Logs, SNS) aren't used. Data is encrypted at rest with AWS-owned keys. CMKs add key-policy control that a single-account, single-team system doesn't need, at $1/month per key.
- **No WAF** in front of CloudFront, which serves only static files. API abuse is bounded by throttling and quotas. Revisit before enabling public self-signup.
- **No S3 or CloudFront access logs, and no versioning** on reproducible or short-lived buckets. The Terraform state bucket *is* versioned.
- **X-Ray** is opt-in. **PITR** is on in prod and off in dev.

## Known gaps / follow-ups

- The CI deploy role is broad (`AdministratorAccess`), constrained by who can assume it. A scoped deploy policy is the next hardening step.
- Bounce events don't yet disable a user's notifications in the app. SES suppression prevents re-sending.
- No per-IP rate limiting at the edge (needs WAF).
